# Existing adapter maintenance during retirement

Read only when the requested fix still needs an existing controller. This is a
compatibility reference, not the recipe for a new adoption. The destination is the
shared tutor/JEV workspace described in SKILL.md. Read the retirement handoff and
census before changing consumers; refresh their status against actual imports and
entry points. Preserve unfinished work and outstanding findings.

## Maintain one owner

Inspect `useNumberLineRuntime.ts` for a component-checked, tutor-led adapter and
`useTenFrameRuntime.ts` for existing runner-control compatibility (both under
`my-tutoring-app/src/components/lumina/primitives/visual-primitives/math/`). Inspect
actual call sites: a runner-shaped type import alone does not prove an executing
runner. Do not copy a reference's ownership, mode gates or assertions blindly.

Where a runner still owns progression, do not offer a competing tutor `advance`.
Where a checked component owns grading, reuse its real learner handlers and require
checked correctness before advancement. Retry retains attempt and assistance history.
Replaying must re-present something; a successful no-op is not a replay. Only a
controller that queues its own instruction may declare runner-owned response speech.

An actual `useJudgedScriptRunner` consumer must receive its runtime where suspension,
speech holds and completion rely on it. Keep these controls working until replacement
is verified; do not expand sentinel/correction packs as the default for new surfaces.

## Execution and help

- `execute()` returns success only after a synchronous committed change. Use committed
  state/refs, a stable mount and the existing change publication mechanism. Refuse
  late commands after item changes, stop, unmount or suspension. No async false success.
- Distinguish an action's phase gate, its visible effect and assistance/exposure.
  Runtime policy can filter offers without throwing: inspect actual policy and
  validator behavior when an action disappears. Do not weaken policy to make a test pass.
- In runner-owned adapters, `canYieldForHelp()` can gate the entire action set.
  Withhold only `supportArtifacts` when a mode cannot support a detour but can replay
  or show a reminder. Check the current runtime's ownership rules before editing.
- The runtime synthesizes prepared support/return from suspension and artifacts.
  Quiesce every timer, pending judgment, queued cue and hidden learner handler.
  Restore the same item and meaningful work. Check whether the owner resumes its
  old phase or intentionally re-arms after discarding an abandoned judgment.
- A text reminder must be described as text. A Pip target is not an executable action.
  Advertise a misstep-specific aid only when published evidence distinguishes that
  misstep; give each strategy its own identity, gating and fading. Do not erase help
  history when fading. Re-derive example checks from the relationship being taught.

## Migrate without discarding the task

Extract domain assignment builders, aliases, constraints, response checkers and
rendering before deleting cue packs. Preserve lawful stimulus timing, grade/topic
scope, accessibility, audio mechanics and evaluation provenance. Controlled wording
may remain instructional content; it must stop acting as verdict transport.

Use the existing census for each mode and entry point. A migrated live mode does not
retire its standalone path or siblings. Remove shared runners, sentinel contracts and
backend paths only after their final executable consumers migrate and reusable voice
infrastructure is retained. Keep tests protecting legacy behavior until that consumer
is actually replaced; then replace exact-wording/miss-cap assertions with the shared
behavioral matrix. Do not retain a permanent parallel teaching architecture.

Use the same registry and generic connected harness as workspace adoption. For any
retained support detour test, preserve non-empty work and capture the support/return
receipts at the transition. Regress affected legacy behavior when changing shared
runtime code, and state the deletion blocker and next migration step in the handoff.
