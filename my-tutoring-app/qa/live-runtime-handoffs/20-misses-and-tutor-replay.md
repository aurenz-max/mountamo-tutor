# What a wrong answer shows, and checking the tutor without Live

Date: 2026-09-27 · **Top priority (user ruling)** · Executors: `/add-support-tiers` (misses, levers), `/add-live-tutor-tools` (replay, policy) · Pilot done: number-line `jump`

## Why this exists

Every live-tutored item raises three questions. Only the third needs a model, and only its timing part needs a Live session:

| Question | Where it is answered | Cost |
|---|---|---|
| 1. Does the screen do the right thing on a right or wrong answer (credit, retry, advance, nothing revealed)? | code: the dry journey `runtime/journeySweep.test.tsx`, all 152 payloads | free, ~20 s |
| 2. What does this wrong answer show, and what comes next? | code: the check names a **miss**; each lever declares the misses it answers; `nextLever` picks | free (vitest) |
| 3. Does the tutor say something useful, without giving the answer? | a model: one **text call** with the tutor's real instructions and the packet (Part C). Live only for turn timing and real audio | text calls; Live rarely |

Until now question 2 was answered by the Live tutor reading prose (`when: 'The learner lands one hop off...'`), and question 3 had no tier between vitest and a paid Live session, so every primitive's gate was Live (39 lever-bench runs on 09-27 alone). This handoff moves 2 into code for every primitive, builds the missing tier for 3, then changes the per-primitive gate so the roadmap no longer depends on Live runs.

## User rulings (2026-09-27), do not reopen

1. Top priority, ahead of handoff 19 slices 1-4 (those continue after Part A1).
2. Anything code can decide is code and tested by vitest, never by a Live run.
3. A miss names the observable pattern ("one hop short"), never a guessed cause ("counted the start"); causes stay with the tutor and the distiller.

## The contract (built 09-27, number-line is the reference)

- Check: `progress.commitCheck(describe, correct, miss)` or `commitGesture({ response, correct, miss })`. Lands on `TeachingAttempt.miss` and reaches the tutor in the packet.
- Domain module: a pure `<x>Miss(item, work)` beside the check (`jumpMiss` in `numberLineLevers.ts`).
- Catalog: `teachingWorkspace.misses: { <evalMode>: [ids] }`. Sweep rule J8 then fails any checked miss on that mode that names nothing or an unlisted id.
- Levers: `WorkspaceLever.answers: [miss ids]`; shared `nextLever(levers, miss)` (`runtime/observerLever.ts`).
- Tests: `it.each` over the miss function (work → miss) and, with levers, over `nextLever` (miss → lever) (`numberLineLevers.test.ts`, `NumberLine.levers.workspace.test.tsx`).
