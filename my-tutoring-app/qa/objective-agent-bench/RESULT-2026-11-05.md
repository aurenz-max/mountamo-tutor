# Agent-composed lessons vs the manifest — CLOSED 2026-11-05

Question: does replacing the manifest with agents that compose primitives (real generators,
read back, revise) add content variety, and at what latency?

Bench: `scripts/objective-agent-bench.mjs`. Runs `r1.json` (manifest vs one agent per objective,
4 topics) and `r2-single.json` (one agent for the whole lesson, 2 topics). Spend about $2.9.

| Arm | First primitive | Full lesson | Cost / lesson | Distinct primitives |
|---|---|---|---|---|
| manifest | 25-36 s | 76-138 s | $0.13-0.21 | 6-10 |
| one agent per objective | 10-17 s | 55-156 s | $0.22-0.53 | 3-7 (same primitive + mode across objectives) |
| one agent for the lesson | 15-38 s | 82-179 s | $0.13-0.23 | 3-4 (built 1-2 per objective, never revised) |

**Verdict (user 11-05): keep the manifest.** Agents did not add variety. Both the manifest and
the agents pick from the same catalog lines and settle on the same few primitives. The one real gain,
an earlier first primitive, came from starting generation before the whole plan exists. That
is streaming, and the manifest can do it.

Every lesson is saved as a Lesson Package in `packages/` (drop on the Lesson Bench panel) and
indexed in `library.jsonl` (topic, objectives, picks with eval mode and intent).

## Parked (user 11-05)

- **One DI agent instead of several separate DI primitives.** A lesson with several
  `di-*` primitives might work better as one tutor-led agent that has every DI capability
  (explain, deduce, spoken practice). Resume only by user choice.
- **Retrieve and reinvent.** A later lesson could retrieve a past lesson's plan (picks + intents
  from `library.jsonl`) as the manifest's starting point, while content is still generated live.
