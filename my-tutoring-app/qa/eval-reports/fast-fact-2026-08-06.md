## What changed

### FF-1a — the visual IS the answer (CRITICAL)

The missing invariant was **representation shift**: the visual and the options must be
different representations of the fact. Three layers had failed, and all three were closed.

- **Prompt** ([gemini-fast-fact.ts](../../src/components/lumina/service/core/gemini-fast-fact.ts)) —
  the self-contradicting pair at the old lines 401-402 ("NEVER reveal answers in … visual
  content" immediately followed by "use `text-large` for symbols") is replaced by an
  explicit REPRESENTATION SHIFT block with the live counter-examples (`Fe`→Iron ✅,
  `7`→`7` ❌, `the`→`the` ❌), a NEVER-NAME-THE-ANSWER block, and per-subject shapes that
  say what to generate *instead*.
- **Code** — `visualLeaksAnswer` + `resolveLeakingVisual` in `reconstructChallenge`. A
  leaking `text-large` is REJECTED (the large text *is* the stimulus, so the item's whole
  task was pixel-matching — nothing to salvage); a leaking emoji is STRIPPED when the
  prompt stands alone, rejected when the stem points at it.
- **Schema** — `visualContent`'s description now states the constraint at the field.

**The prompt half is load-bearing, not decorative.** For sight words, "show the word, pick
the word" is identity-shaped by construction — a code guard alone would have rejected the
entire LA drill and shipped nothing. Teaching the replacement shape is what actually fixed
it. Live proof, same topic that leaked 10/10:

```
was:  "Which word is this?"  + text-large "the"  → the / and / big
now:  "Look at ___ happy dog!"  (Fill in the missing word) → a / the / to
```

### FF-1b — the stem names the answer (CRITICAL)

`stemLeaksAnswer` rejects a challenge whose prompt names or quotes its own key while
naming no distractor. Computation stems are exempt (in `7 + 3` the operands are the
problem). Short function words only count when quoted, so *"Which word finishes **the**
sentence?"* with the key `the` is not a false positive. Catches all three live shapes:
*"Which option spells 'and'?"*, *"Find the word: look"*, *"What is the final number when
counting to 20?"*.

### FF-2a — position clustering (HIGH)

`placeAnswerAtSlot` rotates the key across slots from a per-drill random offset. Rotation
rather than shuffling because random placement does not guarantee a spread at n=10; a
random offset rather than bare `index % n` so the pattern is not learnable across sessions.
Live: `{0:3, 1:3, 2:3}` — was slot 1 in 8/10 and 9/10.

### FF-2b — duplicate / doubly-correct options (HIGH)

`normalizeOptions` deduplicates case-insensitively, then keeps only the first option that
grades correct under the component's own predicate. This closes both live shapes at once —
the literal `[New Mexico, Nevada, Arizona, Arizona]` (a React `key={opt}` collision **and**
two correct buttons) and the subtler case where `acceptableAnswers` silently promotes a
distractor.

### Two silent fallbacks removed

`reconstructChallenge` shipped a `'???'` sentinel key when Gemini omitted the answer, and a
single-option "pathological" challenge when it produced no distractors. Both are now
rejections — unwinnable and free-win items respectively. Rejections are tallied and logged;
a drill with **zero** survivors throws rather than rendering an empty card.

### FF-3 — emoji shown ≠ numeric key (CRITICAL, found by re-testing, fixed same slice)

**Not in the input report — the first post-fix run surfaced it, at 2/50.** Steering counting
items onto emoji (so the numeral stops being displayed) walked straight into SP-8: flash-lite
writes *"the key is 10"* and then emits seven faces, and a child who counts correctly is
marked wrong.

Closed structurally rather than by detection. A new `visualRepeat` schema field asks the
model for a **number** it can get right; `buildEmojiVisual` repeats the glyph in code. The
model no longer has to physically emit N glyphs, so the failure mode is removed at its
source instead of being caught afterwards. Legitimate derived-count items are unaffected
(🖐️🖐️ keyed 10 has `visualRepeat: 2` and stays two hands).

## Honest residuals

1. **The oracle's leak checks are now regression detectors, not independent discoveries.**
   The generator enforces the same contract the oracle verifies, so a green oracle run no
   longer proves the content was authored well — only that the guard is still wired. The two
   implementations are deliberately kept separate (no shared code) so a bug in the guard
   still fails the oracle, but do not read this PASS as independent confirmation of authoring
   quality. Judging that stays `/eval-test`'s and a human's job.
2. **No browser check.** No component change shipped, and the oracle reads data rather than
   pixels. A K counting drill rendering 19 flower emoji in the `text-5xl` visual box has not
   been looked at — the 25-glyph cap is a guess at what fits.
3. **Drill length under rejection.** The user ruled reject-only (no retry), so a leak-heavy
   topic can ship a short drill. Measured impact was small — Math ran 9,9,10,10,9 (one
   stem-leak rejection in 3 of 5 runs), the other three subjects 10/10 — but a topic where
   the model insists on leaking will ship below the 8-12 contract, and a total leak throws.
4. **`fast-fact` is still L0** — `supportsEvaluation: true` with no `evalModes`, so it is
   absent from the evaluable count and unrouteable by difficulty. Left queued as FF-4
   (`/add-eval-modes`), untouched here.
5. **TU-1 left open** by user ruling — the spoken-scaffold leak is a separate channel.
