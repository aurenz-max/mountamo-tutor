## What was actually wrong

The handoff's diagnosis — that the `apply` identity was "partly cosmetic" — was
correct, but the mechanism was not in `CHALLENGE_TYPE_DOCS.apply`. It was one
section lower, in the part of the prompt nobody was looking at.

`${challengeTypeSection}` renders *"Generate ONLY the following challenge
type(s): apply"*. Six lines later, unconditionally, the prompt said:

```
## Phase Design:
- Generate challenges across 2-3 PHASES (e.g. 'recall', 'apply', 'rapid-recall').
- Early phases should be easier; later phases should be harder ...
```

So the model was handed back the vocabulary it had just been forbidden
(`'recall'`), plus an instruction to soften the **first phase**. It complied with
both: phase 1 was built as ordinary direct recall, phase 2 as genuine apply.
Every item was still stamped `challengeType: "apply"` — not because the model
believed it, but because `constrainChallengeTypeEnum` had left the schema enum
with no other value to write. **The stamp was the only thing the constraint ever
reached.** That is the exact reported signature: 2 phases, first 5/10 direct.

This is SP-3 with a twist worth recording: the contaminating text was not another
mode's `promptDoc`. It was a *presentation* instruction whose example values
collided with the *task-identity* vocabulary. Two axes, one namespace.

## Fixes — all PROMPT-CHANGE, no new validators

Per the handoff's constraint, no semantic post-validator was added. "Is this
stem contextual?" is not decidable across every subject FastFact serves, and
rejection would shorten the drill below its automaticity floor.

### 1. Separate the presentation axis from the task axis
[`gemini-fast-fact.ts`](../../src/components/lumina/service/core/gemini-fast-fact.ts)

- Phase-name examples changed from `'recall', 'apply', 'rapid-recall'` to
  `'warm-up', 'core', 'mastery'` — named for **place in the drill**, never for a
  task identity.
- New `phaseIdentityLine`, emitted only when a mode is pinned or blended:
  *"'Easier' means easier CONTENT — it NEVER means a different task shape. EVERY
  challenge in EVERY phase, including the first, must be "apply" as defined
  above. A phase is a place in the drill, not a task type."*
  It interpolates `resolution.allowedTypes`, so a blend names both identities and
  a genuine mixed run emits nothing.

**Measured effect:** phase names went to `warm-up/core/mastery` in every pinned
run, and the first-phase downgrade stopped.

### 2. Scenario wrapping is not application
`CHALLENGE_TYPE_DOCS.apply` — closes the residual the reproduction found:
*"If you are mailing a letter to the capital of Ohio, which city are you
addressing it to?" → Columbus.* Direct state→capital in costume.

### 3. One handle, and a worked GOOD/BAD contrast

Iterations 1–2 were prose prohibitions, and they held for state capitals,
multiplication and sight words — but **element symbols bled 2 runs out of 3**,
producing 10/10 symbol→name with a use-sentence bolted on. Prose had named the
right rule twice and been ignored twice, so the lever was changed rather than
lengthened: a GOOD/BAD example block, the same device that carried the FF-1 fix
in this file.

```
Many drill topics have exactly ONE learned pair (symbol/name, state/capital,
word/meaning). On those topics the ONLY apply shape is to reach one side of the
pair through something OTHER than the other side:
GOOD "Which element symbol is on the tank of a gas that makes balloons float?" -> He
GOOD "Denver is the capital of which state?" -> Colorado
BAD  "Which noble gas is represented by the symbol He?" -> Helium   (recognize)
BAD  "The gas used in balloons has the symbol He. What is it called?" -> Helium
BAD  "What is the chemical symbol for silver?" -> Ag                (recall)
```

**Measured effect:** element symbols went from 20/30 bleeding to **30/30 clean.**

## Residuals

1. **Not browser-driven.** Every run above is real Gemini generation through the
   eval-test API. Nobody rendered a FastFact card in Chrome this session; the
   component was not modified, so the risk is low, but this is not a UI sign-off.
2. **`apply` remains prompt-bound and therefore stochastic.** It is now 50/50
   across four topics, but the binding is prose + examples, not code. Element
   symbols was the hard case and needed a third lever; a new one-pair topic could
   in principle behave like it did. The mechanical `apply` predicate is not safely
   decidable across subjects, so the honest guard is a re-probe on any new
   subject family, not a validator.
3. **`mixed` still lets the model name a phase `'recall'`** (observed in
   `v3_mixed2`). Harmless — in mixed every identity is licensed and
   `phaseIdentityLine` is deliberately empty — but the phase/identity namespace
   is only separated where it was load-bearing.
4. **TU-1 stays open** by user ruling (spoken channel `{{correctAnswer}}` leak in
   the tutoring config). Untouched by this work.
