# Deep dive (agentic author) — roadmap

Owner of the agentic DeepDive (`service/core/deep-dive-agent/`) and generated displays
(`service/gen-display/`). Pull the top open item.

## Built 11-04/05 (committed cd673d56)

- `embed_primitive`: drawers as sections (menu from the catalog's affordances). Bench: 2 of 4 reading-grade lessons embed one.
- `add_see_also`: 2-4 links under a finished lesson, opened through the follow-up path (which can also embed drawers).
- Outline-first lessons: `plan_lesson.sections` (heading + key ideas); blocks carry `section` + `ideas`; code checks coverage (every idea taught, every check tests an idea taught above it, 2-4 blocks per section); reviewer names up to 2 missing essential ideas. Page shows section headings and a contents list.
- Generated displays pilot: kit (`sdkSource.ts`), compile + static checks, sandboxed page (no network, opaque origin), headless harness (probes + screenshots), `create_display` authoring loop with a vision judge, file library (`data/gen-display`), `use_display` / `request_display` in the agent, `GenDisplayBlock` iframe. One seed template (two lines meet). Smoke: `node scripts/gen-display-smoke.mjs`.
- 11-05: coordinate-graph choices shuffled in code (live probe: key at A/B/C/D 4/5/2/4 of 15). Deep dive agent choices were already shuffled (bench: 18/17/7/15 of 57).

- 11-05 DD-4 native math: `utils/mathText.ts` (`$...$` split, `mathIssues` check, `spokenMath` LaTeX to words, `repairMath`), kit `LuminaMathText` in every deep-dive block renderer, headings, contents, See also and the fill-blank slot; prose with math flows as plain paragraphs (the line-measuring renderers would split an expression). - 11-05 DD-11 four display blocks: `chart`, `number-line`, `definition`, `passage` (types + `blocks/InsetBlock.tsx` over the knowledge-check inset renderers, with a tutor ask). Agent tools `write_chart|number_line|definition|passage` with build errors (2-12 points, pie 2-6 non-negative, line >= 3 points; number-line step splits the range into <= 20 parts, points and region in range; plain-text labels; attribution required except prose) and checks (definition must not use its own term; passage <= 120/200/300 words by grade; passages exempt from the sentence-length rule). Evidence: bench `qa/deep-dive-bench/dd11-insets.json` (g4 railroad: definition + passage "Adapted from Harriet Tubman"; g5 climate: definition, agent chose a data table over a chart; g6 integers: number line A-D + definition, 104 expressions, 0 math issues; $0.19); headless drives of each new block, 0 page errors.
- 11-05 DD-12 `worked-example` block: problem, 2-6 steps (work + reason) revealed one at a time, answer at the end. At apply/analyze (`tierModes.workedTry`) code requires a try step: the student picks that step's line from the real one and three agent-named errors (code shuffles; graded item, spoken key is the spoken math); later steps stay hidden until it is settled, then the rest and the answer show at once (the shell closes a checked block until Next challenge, which first locked the remaining steps; caught in the drive). Agent: `write_worked_example`; build errors for step count, try step range, repeated lines. New check on every block: an all-numeric equation that is false ("$2(4) + 3 = 12$") blocks (`falseEquations`, mathjs via `tryEvaluateKatex`); 0 false alarms on 28 equations in earlier lessons. Evidence: bench `qa/deep-dive-bench/dd12-worked.json` (g7 two-step equations and g8 systems, both chose a worked example with a try step; distractors are real slips; $0.15); headless drive: wrong pick keeps steps hidden, shell Try again, right pick reveals all 4 steps + answer, 0 page errors.
