Short answer

Each graded mode gets up to two levers, designed from why learners fail it. A help lever makes the representation show more on the same item. A simplify lever builds an easier practice item in code, leaves it ungraded, and then brings back the full item. The difficulty tier does not add levers. It only decides which levers start out pulled.

Code decides when a lever is pulled, from the named miss. The learner's first wrong answer gets no lever. The tutor responds to the miss and the learner tries again. A second wrong answer on the same item, or "I'm stuck" after any wrong answer, pulls the help lever that answers the latest miss. "I'm stuck" before any attempt pulls help only. If the learner is still wrong with help pulled, the simplify lever is pulled next. The tutor can pull a lever at any time; nothing waits on a timer.

How a primitive counts as done: it passes a vitest gate with five tests (miss table, lever leak rules, trigger table, J9 coverage, mounted pull). Once every primitive in a class passes, 1-2 Live runs cover the whole class. Math runs as four classes of primitives that are already bound and name their misses. Literacy and core follow the same method and are handed off below.

Two kinds of lever, and where "tiers" fit

help The screen shows more

The item stays the same, and the representation shows or does something extra. Examples: numbered hops on the learner's own jump, a running count of the counters the learner placed, a model rhyme pair next to the item, a spotlight on the passage line the question was written against.

The attempt after a pull is recorded as assisted, with the lever named. It is never counted as a first-response success.

simplify The same task, one step smaller

Code builds a smaller practice item and computes its answer: one operation instead of two, a smaller total, two choices with the far one kept, a teen number with fewer ones. The practice item is ungraded, and the learner then returns to the full item.

Two rules apply. The mode's defining property must survive (R2): a production item never becomes a choice. The practice item must never repeat the learner's item or give away its answer (R3).

Tiers set where the levers start. The generation tier (config.difficulty) only decides which levers are already pulled when the item loads. Easy starts with some help pulled; hard starts with everything released. Content harder than the mode's full item belongs to a harder eval mode, which /add-eval-modes owns.

What triggers a lever

Today only two things pull a lever. The observer pulls one when the learner says they are stuck after a wrong answer (observerLever.ts), and the tutor can call pull_lever whenever it chooses. The observer picks with nextLever: first the lever whose answers lists the item's last miss, otherwise help before simplify. Steps 3 and 5 are new and were ruled by the user on 09-27, as were the rules for pulling before any attempt, removing a choice, and single-try items. Every step stays in code, so each one is a row in a vitest table.

  1. Item loads: the tier sets the starting leversEasy starts with the first help lever pulled when that lever doesn't give away the answer. Medium and hard start with nothing pulled. Generation · exists as flags on most primitives
  2. First wrong answer: name the miss, no leverThe check names the miss (TeachingAttempt.miss). The tutor responds to what the miss shows without giving the answer or the fix, and the learner tries again. An unaided second try is the most useful evidence we get, so no lever is pulled yet. Code names the miss · tutor responds · exists for gesture families
  3. Second wrong answer on the item: pull helpCode pulls nextLever(levers, lastMiss), restricted to help levers. A repeated miss means the learner cannot see the structure, and help keeps the full item on screen. Observer · NEW (ruled 09-27)
  4. "I'm stuck" after any wrong answer: pull the next leverThis is the current rule, unchanged. Help comes first; simplify comes if help is already pulled. Observer · exists
  5. Wrong again with help pulled: pull simplifyThe learner gets an ungraded practice item built by code, then the full item comes back. Only an answer given on the full item without a lever is credited, and the first-response gate scores the item as not first-try. Observer · NEW (ruled 09-27; the lever mechanism exists)
  6. "I'm stuck" before any attempt: pull help onlyA learner who asks for help before trying gets the first help lever and never a simplify lever. The attempt that follows is recorded as assisted. Observer · NEW (ruled 09-27)
  7. At any time: the tutor may pull on its own judgmentFor example after silence, a hedge, or a spoken answer the tutor judged wrong. Silence is never a code trigger: no timers (ruling: the tutor owns the clock). Tutor · exists

Spoken modes

About 30 families are answered aloud and name no miss until spoken_miss is wired (Phase 1.4, blocked on runtime/). Until then a wrong spoken answer, as judged by the tutor or JEV, feeds the same ladder without a miss, so nextLever falls back to help first. This is enough to build and test the levers now. Picking a lever to fit the miss arrives later without changing the levers.

Items with only one try

Some items allow a single tap: fact-file, the multiple-choice questions in timeline, vocabulary and how-it-works, and fast-fact on the hard tier. A trigger that needs "the second wrong answer" never fires on them. Ruled 09-27: pulling a lever grants one assisted try on the same item.

Math plan

The classes are ordered by readiness. A primitive needs a workspace binding and a miss function before a lever can be triggered by code, so classes M1-M4 all have both. The grade 6-12 tools are priority 3 and not scheduled.

M0 · Fix the answer leaks first /eval-fix

A lever measured on content that already gives the answer away measures nothing (brief B2). Five fixes, listed in Fix first: regrouping-workbench, comparison-builder easy tier, shape-builder target ghost, analog-clock legend guard, plus the flags that must never become levers.

M1 · Number manipulatives class 1 4 primitives · bound · misses named

counting-boardnumber-bondbase-ten-blocksplace-value-chart

These reuse what ten-frame already has: a count of the learner's own actions (running_count, which counts only placed items and never the target) and a smaller-total simplify lever. Base-ten gets a trade-model help lever. Place-value's modes are defined by digit count, so simplify must keep the same number of digits (a same-width number with no zero); dropping a digit breaks the mode floor. Then the Live pair for the class.

M2 · Compare and order class 2 4 primitives · K-1

comparison-buildercompare-objectsnumber-sequencerordinal-line

The core help lever is match_pairs. It draws one model line, then draws only the pairs the learner taps, which replaces the easy tier's leaking live correspondence. For ordering, simplify gives fewer cards but never a subset of the item's own values (R3). Many sequencer and ordinal modes are spoken, so only the gesture modes use miss-driven triggers until Part B.

M3 · Operations and facts class 3 5 primitives

addition-subtraction-sceneequation-buildermath-fact-fluencybar-modelstrategy-picker

Help makes the quantities concrete: a counter strip beside the equation, or the bar split into the learner's own parts. Simplify uses smaller addends or one step instead of two, with the answer recomputed. Fact fluency gets no timer (standing ruling), and speed_round has no simplify lever because a smaller item would cross the mode floor. Strategy-picker's compare mode has no wrong answer, so it gets no lever.

M4 · Patterns, charts, space, money class 4 6 primitives + the remaining modes of the 3 built ones

pattern-builderhundreds-chartspatial-scenecoin-counternumber-tracerten-frame (other modes)

Hundreds-chart reuses number-line's learnerHops to number the steps between the learner's own taps, and its simpler skip must share no cells with the item's answer set. Coin-counter gets a running total of the coins the learner has tapped. Ten-frame's showEmptyCount must not become a lever, because it states the make_ten answer.

number-line plot needs plotMiss (one tick off / off by more / far). Balance-scale is bound but has no miss function. The three all-spoken families wait for spoken_miss, and their levers could use help-first order in the meantime.

Rulings (decided 2026-09-27)

  1. agreed A second wrong answer auto-pulls help, with no "I'm stuck" needed. Help levers only.
  2. agreed A pull before any attempt gives help only, never simplify, and the attempt is recorded as assisted.
  3. agreed Removing a choice is assisted work on the same item. The item counts as solved but not first-try, and never as unaided credit. This is the R4 exception for choice items.
  4. agreed On single-try items, pulling a lever grants one assisted try.
  5. open Math class order. M1 → M4 as above, with L1 (literacy phonics taps) allowed to run in parallel because it is ready now.
