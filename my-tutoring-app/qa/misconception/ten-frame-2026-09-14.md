## What was built

**Capture.** `tenFrameEvidence.ts`: `tenFrameObservation` states each item from its own fields (start and number taken
away, both addends, counters shown, frame size, split ordinal) plus what was on screen (printed equation, count readout,
"Show again" taps) and what the learner said, placed or turned yellow; a split carries its code verdict (empty part or
repeat). `tenFrameDiagnosisEvidence` keeps at most 12 phases (every item's first wrong attempt first, emitted in order) and
sets `firstResponseScore`. `TenFrame.tsx` passes one function as `diagnosisObservation` and `responseObservation`, submits
`learningResponses`, and reports the catalog eval mode. Grading and the score are unchanged. Catalog
`misconceptionScope: 'skill'`, `observationDelivery: 'server'`.

**Capability.** `tenFrameRemediation.ts`: one move, described for K subtraction (7−1 then 7−3), K addition within five
(2+1 then 2+3) and Grades 1–2 crossing ten (8+3 then 8+5; 15−7 then 15−9). The description says it does not address an
answer that repeats the number taken away. Gates `eligibleTenFrameTeaching` (grade K, 1 or 2 and mode `operate`) and
`tenFrameDeliveryEligible`. The selector rewrites the second number of one later item to follow its neighbour's first
number, only between neighbours of the same operation, and holds: operations, count, ids, the session's largest answer
and second number, whether the item crosses ten, distinct items, an answer that is never a said number; it prefers a slot
outside a same-second pair the baseline already had. The compiled recheck reads the rendered fields.

**Delivery and execution.** Catalog `learningObservations: { eligible }`; no service or backend edit. The generator plans
in parallel with the item call and applies the selector after every gate, override and fallback, before the support tier
and `buildInstruction`; hint and narration on the rewritten item are app-owned. Contract R11 added.

**Judge fix.** `discriminationFor` on a subtraction double now refuses only the start and states that the number taken
away is also the answer; test in `TenFrame.di-script.test.ts`.

**Rates.** Real baselines (this run plus the pre-build census): the contrast was present by chance in 0 of 11 K
subtraction and 0 of 10 Grade 1 sessions, but in 4 of 6 K addition-within-five sessions (2+1 beside 2+2), which report
`already-targeted`. Simulated over the real generator with the model call replaced (20,000 sessions each):

| Model items | Chance contrast | Capacity miss |
|---|---|---|
| K subtract, ascending starts (what flash-lite returned) | 0% | 0.1% |
| K subtract, uniform / narrow starts 5–7 | 26.2% / 70.5% | 1.5% / 0.3% |
| K add within 5 | 38.7% | 6.2% |
| K add and subtract interleaved at random | 14.1% | 16.0% |
| Grade 1, distinct first numbers (what flash-lite returned) | 0% | 0% |
| Grade 1, first numbers repeated freely / operations interleaved | 52.9% / 8.1% | 0.3% / 19.8% |

Capacity misses come from sessions where no two neighbours share an operation. The change stays inside what the session
already shows, so narrow or interleaved sessions report `already-targeted` or `insufficient-capacity` rather than widen.

**Failed or corrected runs, kept.** Two test fixtures were wrong about the code (a subtraction cannot fail to close because
its key is derived; `2+2` is legal within five) and were corrected, not the code. The first rates smoke run modelled
Grade 1 first numbers as repeating, which real draws never did (50% chance); the distinct-first model was added and both
kept.
