## Affordances and implementation weight

| Destination mode | Existing learner action | New adaptation |
|---|---|---|
| read_blocks | Say a block count, then its total worth | Same nonzero count across two block sizes; code chooses numbers, existing compiler chooses the asked place |
| regroup | Predict and execute one trade | None; worth confusion is not the trade-prediction contract |
| build_number | Construct a numeral in standard form | None in this slice |
| add/subtract | Operate on blocks with regrouping | None in this slice |

The evidence adapter is small: one `responseObservation` callback and the normal student-work ledger. Existing runner, LLM distiller, capture, storage and profile code do the rest. The content adapter is a small pure selector plus a generator call; it changes at most two target numbers, keeping each zero-column pattern, four-digit band, uniqueness, challenge count, mode, support flags and all spoken scripts. The new shared routing wrapper is the first cross-representation cost. Tests and scope review are a substantial part of the work even when the adapter is short. Primitives without rich task/response evidence or a suitable content lever will take more work.
