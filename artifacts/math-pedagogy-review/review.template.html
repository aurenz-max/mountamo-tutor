Real personalization infrastructure

Generation context joins objective-level ability and lifecycle information with a separate persona and active diagnoses. The generation boundary carries scope, eval mode, support tier and private remediation focus. [1–3]

Confirmed capture gate

Hints do not imply diagnosis

Capture exits when the catalog has no misconceptionScope, even if a component supplies evidence. Only tape-diagram, comparison-builder, ordinal-line, sorting-station, 3d-shape-explorer and compare-objects opt in within the math catalog. [4]

Product limitation

Resolution is too coarse for transfer

The Lumina submission branch verifies primitive/skill identity and a score threshold, then resolves after the normal submission fan-out. That branch does not require an unassisted probe, a second representation or a delayed recheck. [5]

Recommended direction: finish a few complete diagnostic teaching loops before enabling capture across the library. For each target, specify the wrong rule, the observation that distinguishes it from alternatives, the response that changes instruction, and the independent evidence that retires it.

Other concrete seams

  • Storage overwrites one active text slot per primitive, or primitive + skill. Multiple hypotheses and their histories cannot coexist in that slot. [6]
  • Confidence and evidence tier are stored, but are omitted from the generation-context misconception projection. The consumer receives the claim without these quality fields. [1,6]
  • The capture latch is set before the distiller returns. An abstention or failed write still consumes that identity's opportunity in the same session. [4]
  • Flattening matches the same primitive, plus skill for skill-scoped records. Cross-primitive conceptual transfer is not represented by this matching rule. [7]

A distinction worth preserving

Ability: how likely is success on a calibrated task?
Misconception: what wrong rule predicts the error?
Support need: what assistance enables success now?
Transfer: does the understanding survive a changed representation or delay?

The code already separates task mode from support tier. Preserve that separation when adding adaptation. A misconception should target a distinction inside the assigned scope; a prerequisite detour should be an explicit planning decision. [3]

The richer state below is a proposal. Its absence from these contracts is not a claim that no related metrics exist anywhere in the repository.

03 / Expand what a primitive can teach

Five stages turn an activity into an instructional sequence.

01 · ELICIT

Predict or build

Capture the first unaided response, representation and chosen strategy before feedback changes the evidence.

02 · DISCRIMINATE

Test the wrong rule

Use a contrast pair where plausible explanations predict different answers. A single incorrect answer remains ambiguous.

03 · TEACH

Expose the relationship

Use a model, worked example, manipulation or explanation task. Make the missing mathematical connection explicit after the attempt.

04 · FADE

Return responsibility

Withdraw one cue, then ask for a new solution. Record whether success required a hint, model or correction.

05 · TRANSFER

Change and revisit

Change the context or representation and later revisit the concept. Keep these probes distinct from coached practice.

Systematic instruction, mathematical language, representations, number lines and word-problem instruction are supported in the 2021 WWC elementary mathematics intervention guide. Combining worked examples with problem solving, retrieval and spaced exposure is addressed in WWC’s learning and study guide. The five-stage software contract above is our design synthesis, not a validated Lumina intervention or a claim that evidence generalizes equally to every advanced primitive.

Reasoning beyond correctness

Add prediction-before-reveal, explain-your-choice, identify-the-invalid-step, compare-two-strategies and construct-a-counterexample opportunities where the primitive supports them.

Evidence: relation chosen, invariant cited, invalid step identified—not just final score.

Bridges across representations

Carry the same mathematical relationship between number bonds, scenes and equations; between blocks and place value; between fraction models and a number line; between ratio tables and graphs.

Evidence: learner-created correspondences and independent solutions in the destination representation.

Language, agency and access

Offer read-aloud, tap/build alternatives and precise comparison language. Let the learner request a representation or explain a strategy. Test whether the chosen support helps on later independent work.

Evidence: access mode, help request and mathematical response recorded separately.

Design guardrail: “more surface area” should mean more observable mathematical thinking. New animation, extra hints or additional task modes count only when they expose a distinct learning decision. Candidate misconceptions below must be validated with repeated or discriminating evidence; they are not diagnoses of actual students.

05 / Recommended build sequence

Finish three coherent loops, then expand by concept family.

Priority reflects prerequisite reach, observable error signatures and the availability of existing representations. It is a product judgment; learner prevalence and effect sizes were not measured.

First new pilot selected: place-value-chart, targeting bare-digit answers when the digit's worth is asked. Open the implementation, harness and demonstration handoff. Status: ready for a new session; implementation and runtime proof are still pending.
First · Make the current loop trustworthy

Capture → consume → confirm

Audit the 6 opted-in math entries and 5 math DI entries. For each mode, prove evidence is emitted, a usable diagnosis persists, content changes for the correct identity, and the next response provides relevant evidence.

Concrete seams: ordinal-line, sorting-station and 3d-shape-explorer have capture opt-in but no remediation marker in their direct generator files. Trace helper paths before declaring them unwired. Tape-diagram already has mode-specific remediation moves; reuse its approach.

Exit: a deterministic trace and a generated payload comparison per supported mode, followed by a browser task showing the intended teaching behavior.

Second · Place value and regrouping

One concept, several expressions

Connect base-ten-blocks, place-value-chart, regrouping-workbench and di-worked-procedure around unit conservation. Capture exchanges, column state and spoken moves.

Target: “renaming a unit changes how many units of each kind are written, while conserving the total.” Keep the DI subtraction scope limits; do not introduce unsupported across-zero cases there.

Exit: distinguish a source-column decrement error from an arithmetic slip, teach the exchange, then verify in an unprompted second representation.

Third · Fractions and the whole

Make transfer visible

Connect fraction-circles, fraction-bar and number-line around equal partitions, the reference whole and magnitude. These math entries currently lack capture opt-in.

Target: separate unequal-part counting, denominator-as-magnitude and mismatched-whole comparisons. Test each with a discriminating contrast.

Exit: the learner succeeds on an unseen comparison, justifies the unit whole and later transfers from an area model to a number line.

Then extend the same contract

Story structure: number-bond → addition-subtraction-scene → tape-diagram → equation-builder / di-word-problem-setup.
Multiplicative reasoning: array-grid → area-model → multiplication-explorer → ratio-table / double-number-line / percent-bar.
Equality and functions: balance-scale → equation-workspace → function-machine → coordinate-graph / slope-triangle.
Measurement and data: length-lab / measurement-tools → scaled graphs → distributions, with units and reference groups made explicit.

These are proposed bridges, not claims that every destination currently supports the same grade or mode. Route only curriculum-compatible tasks through the existing lesson composer and objective contract.

06 / Sources, method & limits

What this review establishes.

This is a source audit and design artifact, not a live learner-data study. The inventory was extracted from the current working tree using the TypeScript AST. Existing uncommitted fraction/base-ten work is included in the snapshot and was not modified. All 69 entries have linked generator and component files; badges examine those direct files only. No authenticated learner records, generated lesson runs, tutor sessions or backend behavior tests were used to validate educational effectiveness.

The reviewed math catalog contains 63 entries despite its older “25 components” header. spatial-path is registered in mathGenerators but absent from MATH_CATALOG; this review does not establish whether another launch path exposes it. bar-model currently describes categorical bar/picture graphs. A DI word-problem catalog constraint still suggests it for drawing a model; that wording conflicts with its current catalog home and deserves cleanup.

Older misconception docs and several current comments describe subskill-keyed storage or filtering. Executable code now keys records by primitive or primitive + skill; get_active_misconceptions currently reads all active records without applying its optional subskill filter. This review follows the implementation, then separately labels proposed changes.
